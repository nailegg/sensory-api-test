## 3. 공유 사항 (결정 아님)

- **heartbeat 60초**: Google 작업에 `heartbeatSeconds: 60`을 켰다. 만료(`expireInSeconds`) 2시간은 "시작한 지 N초"만 보는 절대 상한이라, worker가 강제 종료된 작업이 2시간 뒤에야 재시도되는 부작용이 있었다. heartbeat는 실행 중 worker가 30초마다 갱신하고 60초 넘게 끊기면 실패로 돌려 1~2분 안에 재시도한다. 살아 있는 긴 작업은 끊기지 않는다. 기존 studio 큐에는 없던 설정.
- **worker 1대 전제**(안건 1과 연결): 배포 체크리스트(studio `TODO.md`)에 있음.
- **배포 전 필수**: 마이그레이션(0010·0011·큐 생성) → API·worker 기동 순서. Google 동의 화면이 "테스트" 상태면 refresh token이 7일 뒤 만료되어 마감 작업이 실패하므로 프로덕션 전환 전 배포 금지.
- **팀원(Zoom) 전달**: worker 권한 두 건의 이유(0010 `external_accounts` UPDATE = Zoom 갱신 토큰 저장용, 0011 = 수집 잠금), Zoom 이식 파일 위치(synsory-api `studio-port/zoom-*.ts`), 연결 흐름을 Zoom으로 넓힐 때 갱신마다 바뀌는 refresh token은 행 잠금 필요, 결정 42(https 리다이렉트)·43, 주석 규칙(기술적 선택의 이유만 영어 한 줄). 목록은 `STUDIO_BRANCH_PLAN.md` 7단계.

## 4. 브랜치에 들어간 것

### 4.1 엔드포인트

| 라우트 | 하는 일 | 입력 → 출력(contracts) |
| --- | --- | --- |
| `POST /api/connections/google/start` | Google 동의 화면 URL. 범위는 "앱이 만든 파일"과 이메일 확인뿐. state와 브라우저 쿠키를 묶어 CSRF 방지 | `googleStartBody` → `googleStartDto` |
| `GET /api/connections/google/callback` | Google이 돌아오는 곳. refresh token을 studio 암호화로 비공개 스키마에 저장하고 웹으로 redirect. 세션 만료 시에도 JSON 401 대신 오류 코드와 함께 웹으로 | 브라우저 redirect(프론트는 안 부름) |
| `GET /api/connections/google` | 연결 여부와 연결된 계정 이메일 | → `googleConnectionDto` |
| `DELETE /api/connections/google` | 연결 해제. 이후 이 계정으로 도는 작업은 실패로 기록 | → `ok` |
| `GET /api/connections/google/picker-session` | Picker용 짧은 access token·API 키·프로젝트 번호. 브라우저 헬퍼 `pickGoogleFile()`이 사용, refresh token은 브라우저에 가지 않음 | → `pickerSessionDto` |
| `POST /api/connections/google/picked-file` | 고른 파일 ID·종류를 서버가 확인하고 제목·URL 반환. 프론트는 ID를 config의 `template_file_id`에 넣음 | `pickedFileBody` → `pickedFileDto` |
| `GET /api/courses/:c/activities/:a/google/status` | 폴더 URL과 조별 항목(조, 종류, 파일 ID·URL, 오류, 사람별 공유 실패). 도구 네 개가 같은 모양 | → `googleActivityStatusDto` |
| `POST /api/courses/:c/activities/:a/google/retry` | 상태에 맞는 작업 하나를 다시 넣음. closed면 재마감+재수집, open이면 빈 조 채우기+권한 복원. 전부 멱등 | → `ok` |

활동 자체의 생성·open/closed 전환·응답 조회·집계는 studio 기존 활동 라우트. 상태 전환 트랜잭션 안의 훅이 worker 작업을 하나 넣고, 처음 열 때 연결이 없으면 409 `EXTERNAL_RECONNECT_REQUIRED` + `details.start`(연결 시작 경로)로 롤백.

### 4.2 worker 작업 (큐 `google-activity` 하나, group = 활동 ID)

- **생성**: 폴더를 만들어 즉시 기록 → 조별 파일(템플릿 복사 또는 Markdown·CSV 업로드) 또는 폼을 만들 때마다 `share_pending`으로 기록 → 공유. 중간에 죽어도 재실행이 파일을 다시 만들지 않고 공유만 마저 한다. 조 실패는 조별 오류로 남기고 다음 실행이 빈 조만 채운다.
- **마감**: 조원 권한을 댓글로 낮추고 폼 응답을 중지한 뒤, 응답을 읽어 100개씩 studio DB에 저장(`CollectionService.commit`, 중복 방지). 폼별 실패는 `collect_error`.
- **재개**: 생성 흐름으로 빈 조를 채운 뒤 조원 권한을 writer로 복원(파일 소유자는 건너뜀).
- 재시도 3회·30초, heartbeat 60초, 만료 2시간, 실패는 이메일·긴 ID를 가린 JSON 한 줄 로그.

### 4.3 도구·DB

- 활동 도구 4개 등록: `google_docs` · `google_slides` · `google_sheets` · `google_forms`(설문·퀴즈·동료평가는 config `mode`). DB 허용 목록 CHECK 갱신(0010).
- worker 권한: `external_accounts` UPDATE(0010), `course_members.updated_at` 열 UPDATE(0011, 수집 잠금용. 행 잠금은 한 열의 UPDATE로 충분함을 실측).
- 연결 저장: refresh token은 AES-GCM으로 `studio_auth.external_accounts`, 연결 계정 이메일 함께 저장.

## 6. 남은 리스크와 브랜치 뒤 할 일

- 남은 리스크: worker 2대 이상(안건 1), 템플릿을 고른 교수자 ≠ 활동을 연 교수자면 전 조 404(가드·안내 없음), 이메일 없는 학생은 공유에서 조용히 빠짐, Forms 응답 읽기 rate limit에 자동 backoff 없음, Google 응답 모양 변화는 작업 전체 실패(의도), 화면 없음.
