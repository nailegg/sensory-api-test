01

공통 전제

인증과 권한

연결하는 사람은 교수자 한 명입니다. 파일·미팅은 교수자 계정 소유로 만들어지고, 학생은 Synsory에 계정을 연결할 필요 없이 Google 이메일만 있으면 됩니다.

Google — scope 1개

  • drive.file 하나로 Docs·Sheets·Slides·Forms 전부 동작앱이 만들었거나 사용자가 고른 파일만 접근. 제한 scope(drive)가 아니라 CASA 보안 평가가 없음
  • 기존 파일은 Google Picker로 고르게 함교수자가 브라우저에서 고르면 그 파일에 접근이 생김. scope 추가 없음
  • 테스트 상태 앱은 refresh token이 7일 뒤 만료재로그인이 필요한 것을 오류로 착각하지 않기

Zoom — scope 6개

  • General App (User-managed) + client secret무료 계정으로 앱 생성 가능
  • user:read, meeting:write/read/update/delete, meeting:read:participant플랜 확인, 미팅 CRUD, 참가자 조회
  • OAuth 리다이렉트와 웹훅을 ngrok 고정 도메인 하나로 받음refresh 직후 이전 토큰도 유효, 앱을 제거하면 토큰이 바로 401

GOOGLE DRIVE · 공통 기반

Drive가 맡는 일

목록·복사·공유·권한·내보내기는 Docs·Sheets·Slides API가 아니라 Drive API입니다. 공통 함수로 만들어 각 서비스가 같이 씁니다.

GOOGLE FORMS · 1 / 3

폼을 만들고 배포하기

폼은 Synsory 템플릿(질문 목록)으로 만들고, 응답자는 수강생으로 제한합니다. 마감은 권한이 아니라 게시 설정으로 합니다.

#유즈케이스핵심 호출상태
1설문을 만들어 게시하고 응답 링크를 학생에게 줌create(미게시) → batchUpdate → setPublishSettings실측
2정답·배점을 넣은 퀴즈isQuiz를 배치 맨 앞에, 문항마다 grading실측
3조마다 동료평가 폼, 그 조원만 응답격자 질문(행=조원, 열=척도) + 조원별 응답자 권한실측
4예전 폼을 Picker로 골라 이번 액티비티용으로 복사Picker → Drive files.copy → batchUpdate실측
5응답자를 수강생으로 제한 + 로그인 이메일 수집VERIFIED + view=published 권한, anyoneWithLink 삭제실측
7마감 시각에 응답 중단, 연장하면 다시 열기setPublishSettings(isAcceptingResponses)실측
8수업 중 미니 퀴즈를 정한 시각에 열고 닫기미게시로 만들어 두고 7과 같은 호출구현 (7과 같은 호출)

GOOGLE FORMS · 2 / 3

응답을 가져와 쓰기

응답의 원본은 폼에 있고, Synsory는 responses.list로 폴링해 가져옵니다. 6·9~13은 모두 같은 호출 위에 서로 다른 집계를 얹은 것입니다.

#유즈케이스결과상태
6제출 현황을 명단과 비교제출·미제출 학생 목록실측
9응답 수집 + 문항별 분포·평균응답 목록, 문항별 집계 (증분 조회)실측
10퀴즈 자동 채점 점수학생 이메일별 총점·문항별 점수실측
11동료평가를 학생별 평균으로 집계평가자·피평가자·항목별 점수 → 학생별 평균실측
12응답을 CSV·xlsx 파일로Synsory 서버가 파일 생성 (추가 Google 호출 없음)실측
13응답을 교수자 Drive의 스프레드시트로 사본Sheets 생성·쓰기 함수 재사용, 액티비티 폴더로 이동실측

응답 알림(Pub/Sub)은 쓰지 않고 폴링합니다. responses.list는 사용자당 분당 180회라 활성 폼만, 분 단위로 조회합니다.

GOOGLE FORMS · 3 / 3

실측에서 확인한 것

Forms는 공식 문서와 실제 동작이 다른 곳이 가장 많았습니다.

문서와 다른 동작

  • API로 만든 폼의 기본값은 "게시"문서는 미게시라고 함. 항상 unpublished=true로 만들고 질문을 다 넣은 뒤 게시
  • "링크가 있는 모든 사용자" 응답 권한이 자동으로 붙음학생을 응답자로 추가해도 이걸 지워야 제한됨
  • 퀴즈에서 틀린 답과 채점 안 하는 문항이 둘 다 grade: {}점수 집계는 폼의 배점(pointValue)을 함께 봐야 함
  • 증분 조회 timestamp >= X는 경계 응답을 다시 줌responseId 기준으로 덮어쓰며 저장

복사 · 내보내기 · API 한계

  • 복사본: 질문 ID 유지, 미게시, 응답자 제한 해제, 응답 없음
  • Forms UI에서 만든 폼도 Picker로 고르면 복사 가능목록에서 클릭해 골라야 함. 원본은 수정하지 않음
  • 시트 사본은 전부 텍스트학번 0은 지켜지지만 점수도 문자열. 숫자 계산이 필요하면 점수 열만 USER_ENTERED
  • API에 없는 것응답 1회 제한 등 설정 대부분, 시트 연결, 파일 업로드 질문 생성. 응답 제출도 API로 못 해 수집 실측은 사람이 제출

ZOOM · 무료(BASIC) 계정

미팅 예약부터 출석 집계까지

무료 계정으로 실측할 수 있는 범위를 유즈케이스로 정했습니다. 6개 모두 구현·실측했습니다.

#유즈케이스핵심 호출
1교수자 플랜 확인 (Basic이면 40분 넘는 예약에 경고)GET /users/me → type
2그룹마다 미팅을 예약하고 참가 링크 반환A안 그룹마다 미팅 (기본) · B안 소회의실 (비교용)
3매주 반복 수업 회의type 8 + recurrence, 회차 목록 함께 반환
4일정 변경·취소 (회차 하나 또는 시리즈 전체)PATCH / DELETE, 회차면 occurrence_id
5Synsory에서 "시작"을 누르면 호스트로 미팅 열기누를 때마다 start_url 조회 → 302. 저장하지 않음
6출석 자동 집계 (표시 이름의 학번으로 수강생 매칭)참가자 입장·퇴장 웹훅 → 접속 짝짓기·겹침 합산 → 출석·지각·결석·미확인

ZOOM

실측에서 확인한 것과 범위

조용히 실패하는 설정 하나와 웹훅 수신 문제를 주의해야 합니다.

실측 발견

  • 소회의실 사전 배정이 200인데 조용히 버려짐계정 설정 "예약 시 참가자를 소회의실에 할당"이 꺼져 있을 때. 켠 뒤 저장 확인
  • 취소한 회차는 사라지지 않고 deleted로 남음
  • 웹훅이 처음 40분간 0건앱 재설치 + 구독 재저장 뒤 수신. 도메인 문제 아님
  • 웹훅 도착 순서가 뒤바뀔 수 있음집계는 도착 순서가 아니라 이벤트 안의 시각으로 정렬. 퇴장 이벤트가 빠질 수도 있음
  • 게스트는 표시 이름 그대로, 이메일은 빈 값그래서 출석 식별을 학번 매칭으로 정함

제외 · 보류

  • 제외: 마감 시 강제 종료
  • 제외: 시작·종료 웹훅으로 상태 추적
  • 보류: 녹화·트랜스크립트·AI 요약Pro 플랜 필요 (월 $16.99)
  • 보류: 로그인·사전 등록 기반 출석 식별학교 계정·Pro 확인 뒤
  • 운영 메모: 학교망에서 ngrok이 차단됨우회 후 사용
